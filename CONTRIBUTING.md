# Contributing to Vulpes

Thanks for looking! Vulpes is a learning project: the code is meant to be read,
so clarity matters as much as correctness.

## Setup

```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install torch --index-url https://download.pytorch.org/whl/cpu   # or the CUDA wheel for your GPU
pip install -e ".[dev,data]"
```

Everything, including the whole test suite, runs on a CPU. No GPU and no downloads needed.

## Before you open a pull request

```bash
pytest                                    # ~15 s on a laptop
ruff check . && ruff format --check .     # the same checks CI runs
```

- Add or update tests for what you change. Tests use tiny models and generated
  text (see `tests/conftest.py`) so they stay fast.
- If a change affects a measured number (speed, memory, loss), say so in the
  PR and update `docs/PLAN.md` with the new measurement.

## The rules of the project

1. **From scratch.** No `transformers`, `peft`, `trl`, `accelerate`,
   `tokenizers`, nanoGPT, LitGPT or similar. Allowed: PyTorch, NumPy, PyYAML,
   safetensors (serialization only), tqdm, TensorBoard, and Hugging Face
   `datasets`/`huggingface_hub` for downloading raw data only.
2. **Human-written, openly licensed data only.** No data generated by language
   models (no synthetic instruction sets, no distillation from other models),
   for pretraining or fine-tuning. New sources need their license documented in
   `docs/DATA.md` and a pinned revision.
3. **Benchmarks are never training data.**
4. **Strict configs.** Settings live in YAML files backed by dataclasses
   (`vulpes/config.py`); an unknown key is an error. New settings get a default,
   validation in `__post_init__` and a line in the docstring.
5. **Explain why.** Docstrings say *why* a piece exists or why it is done this
   way, not just what it does. Type hints everywhere (`ruff` checks this).
6. **Reproducible.** Downloads pin a revision; anything random takes a seed;
   training resumes bit for bit.
7. **No weights, data or logs in git.** They go to GitHub Releases or stay local
   (`.gitignore`). The exceptions are the tokenizer files and `data/identity.jsonl`.

## Where things are

`README.md` has the repository layout; `docs/PLAN.md` has the plan, every
measurement and every design decision (§10). Questions and ideas are welcome as issues.
